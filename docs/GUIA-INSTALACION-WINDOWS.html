Estudio Copylab — guía de instalación paso a paso (Windows)

Para diseñadores que nunca han usado Claude ni la terminal. Sigue los pasos en orden, sin saltarte ninguno. Tiempo total: ±1 hora, la mitad son descargas. Al final vas a tener el estudio completo funcionando en tu PC.

💻 Esta es la versión para Windows 10 / 11. Si trabajas en Mac, usa la otra guía: docs/GUIA-INSTALACION.html. El estudio es exactamente el mismo — lo que cambia son las instalaciones del paso 1, los comandos de la terminal y un par de trampas propias de Windows que están marcadas en rojo. Todo lo demás (comandos de Claude, rutina diaria, reglas de diseño) es idéntico para las dos.
⚠️ Antes de partir, necesitas que Valeria te haya dado:
  • Tu cuenta @copywriters.cl con acceso al Drive de la agencia
  • Una cuenta de claude.ai con plan pago (o el acceso a una del equipo)
  • La invitación al repositorio de GitHub (te llega por correo — hay que aceptarla)
Si te falta cualquiera de las tres, pídesela antes de seguir. Sin ellas la guía se detiene a la mitad.

1Instalar los programas (una sola vez)

Cinco instalaciones. Todas son «descargar → abrir → siguiente, siguiente, listo», pero dos tienen una casilla que hay que marcar y están avisadas abajo.

ProgramaDónde se descargaPara qué / qué marcar
Google Chromehttps://www.google.com/chrome El estudio lo usa por dentro para generar las gráficas. Aunque uses Edge, tiene que estar instalado.
Visual Studio Codehttps://code.visualstudio.com El programa donde vas a trabajar. Baja «Download for Windows» (User Installer) y ábrelo. Marca la casilla «Agregar a PATH» cuando el instalador la ofrezca.
Node.js (versión LTS)https://nodejs.org El motor de render. Baja el instalador LTS para Windows (.msi) y ábrelo. Siguiente hasta el final.
Git para Windowshttps://git-scm.com/download/win 🔴 En Windows NO viene incluido — hay que instalarlo. Es lo que descarga el estudio y lo que sube tu trabajo. Deja todas las opciones como vienen y aprieta siguiente hasta el final.

En la PRIMERA pantalla del instalador marca la casilla «Add python.exe to PATH» antes de apretar Install. Si no la marcas, nada funciona y hay que desinstalar y repetir.

Cómo se abre la terminal en Windows

Vas a usarla poco (casi todo lo hace Claude), pero la necesitas ahora. Aprieta Win + X y elige Terminal (en Windows 10 dice Windows PowerShell). También puedes apretar Win, escribir «PowerShell» y darle Enter.

✅ Cómo saber que quedó bien: en esa ventana pega estas dos líneas, una a la vez, y aprieta Enter: 
node --version
python --version
Tienen que responder algo como v22.x.x y Python 3.12.x. Si alguna dice «no se reconoce como un comando», ese programa no quedó instalado o no marcaste la casilla del PATH — vuelve a bajarlo e instálalo de nuevo.
⛔ La trampa nº 1 de Windows: PowerShell bloquea npm Si en cualquier momento te aparece «no se puede cargar el archivo npm.ps1 porque la ejecución de scripts está deshabilitada en este sistema», no está roto nada: Windows viene con los scripts bloqueados de fábrica. Pega esto una sola vez en PowerShell, dile que S (sí) y sigue con la guía: 
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned

2Descargar el estudio

⛔ LA REGLA MÁS IMPORTANTE DE TODA LA GUÍA El estudio NUNCA va en Escritorio, Documentos, Imágenes ni Descargas. En Windows esas carpetas las sincroniza OneDrive, y OneDrive «libera espacio» dejando los archivos en la nube en silencio: todo funciona dos días y después muere sin aviso, con errores de archivos que no existen y renders que se cancelan solos. Ya nos pasó dos veces (en Mac fue iCloud, es exactamente el mismo problema). El estudio vive en una carpeta llamada copylab directamente en tu usuario —C:\Users\tunombre\copylab— y los comandos de abajo la crean solos en el lugar correcto.

2.1 — Acepta la invitación de GitHub: revisa tu correo, busca un mensaje de GitHub que dice «invited you to collaborate» y aprieta Accept invitation. Si no tienes cuenta de GitHub, créala primero en https://github.com/signup con tu correo @copywriters.cl.

2.2 — Abre PowerShell (Win + X → Terminal) y pega estas líneas de una vez, todas juntas, y aprieta Enter:

git config --global core.longpaths true
mkdir "$HOME\copylab" -Force
cd "$HOME\copylab"
git clone https://github.com/valeria272/dise-o.git "EDITOR VIDEOS"
cd "EDITOR VIDEOS"
git checkout estudio/sistema-de-marcas
npm install

La primera vez, git te va a pedir iniciar sesión en GitHub (se abre el navegador — usa tu cuenta que aceptó la invitación). Después npm install descarga dependencias por varios minutos: es normal, espera a que vuelva a aparecer el cursor. En Windows suele tardar más que en Mac porque el antivirus revisa cada archivo — no lo interrumpas aunque parezca colgado.

⚠️ La primera línea no es opcional. core.longpaths true le permite a Windows manejar rutas largas. Sin ella, npm install falla a la mitad con «Filename too long», porque Windows corta los nombres de archivo a 260 caracteres y las dependencias del estudio se pasan.
✅ Cómo saber que quedó bien: pega esto en PowerShell: 
Get-Item "$HOME\copylab\EDITOR VIDEOS\CLAUDE.md"
Si te muestra el archivo (y no un error rojo), el estudio está descargado.

3Instalar Claude en VSCode

  1. Abre Visual Studio Code.
  2. Menú File → Open Folder… y elige la carpeta C:\Users\tunombre\copylab\EDITOR VIDEOS.
  3. Si VSCode pregunta «Do you trust the authors of the files in this folder?», responde Yes, I trust the authors. Si dices que no, Claude no puede trabajar.
  4. En la barra izquierda, aprieta el ícono de Extensiones (cuatro cuadraditos) o Ctrl + Shift + X.
  5. Busca «Claude Code» (el editor es Anthropic) e instálalo.
  6. Aparece el ícono de Claude — ábrelo e inicia sesión con la cuenta de claude.ai que te asignaron.
✅ Cómo saber que quedó bien: en el chat de Claude escribe «hola». Si responde en español y menciona el estudio o las marcas, está leyendo el proyecto correctamente.

4.b — Las herramientas de imagen: Magnific y Higgsfield (léelo completo, acá se pierden los días)

Lo primero que hay que entender: son dos cosas DISTINTAS y se conectan de forma distinta. Confundirlas es exactamente lo que hace perder un día entero.
  • Magnific (= Freepik) es el generador de imágenes de la casa — fondos, ambientes, escalado, reiluminación. NO es un conector: funciona con una clave que se instala una sola vez en tu PC (abajo). No hay nada que activar en claude.ai.
  • Higgsfield es solo para video IA / UGC / personajes. Ese sí es un conector de claude.ai, y además necesita que la cuenta tenga créditos.

La clave de Magnific ya no se pega a mano (cambió el 02-09-2026). Viene dentro del proyecto, guardada bajo llave. Se monta con un comando:

  1. Abre PowerShell (Win + X → Terminal).
  2. Entra a la carpeta del proyecto y corre:
python scripts\llavero.py abrir

Te pide la contraseña del llavero del estudio — una sola, te la da Valeria una vez, y este computador no te la vuelve a pedir. Con eso quedan listas la clave de Magnific, la de Anthropic y el acceso al Drive para subir entregas.

Ojo: en Windows el comando es python, no python3. Si te dice que falta cryptography, corre antes python -m pip install cryptography certifi requests (los tres: sin certifi el llavero abre pero la comprobación de Magnific falla).

⛔ Se acabó el pegar la clave a mano. Si ves una instrucción con Set-Content ... .magnific_key o echo clave > archivo, está vieja: ignórala. Esa era además la causa nº 1 de «mi clave es inválida» en Windows, porque PowerShell guardaba el archivo en UTF-16 y el estudio no podía leerlo. El llavero lo escribe bien solo.
✅ Cómo saber que quedó bien: en el chat de Claude escribe: «verifica mi clave de Magnific sin gastar créditos». Claude hace una consulta de estado a la API (no genera nada, no gasta) y te dice si la clave responde. Si responde, ya puedes pedirle fondos y ambientes IA con total normalidad.

  2. Cuando pida iniciar sesión, usa la cuenta Higgsfield del equipo: correo contacto@copywriters.cl. ¿La contraseña? Sale del mismo llavero: en PowerShell, dentro de la carpeta del proyecto, corre python scripts\llavero.py logins y te la muestra junto con la lista de conectores que tienes que activar.
  3. Cierra el chat y abre una conversación nueva (regla de todo conector).
  4. Prueba: escribe «revisa el saldo de Higgsfield».
⛔ Si Higgsfield dice que no hay créditos, NO es un problema tuyo ni de conexión — la cuenta está sin saldo y solo Valeria puede recargarla. Avísale y sigue trabajando: todos los fondos e imágenes del estudio salen de Magnific, que funciona con la clave de arriba y no depende de esos créditos. Que no se te vaya el día peleando con Higgsfield por algo que Magnific hace mejor para gráficas.
✅ Cómo saber que quedó bien: en un chat nuevo escribe: «busca la carpeta AGENCIA COPYWRITERS en Drive». Si la encuentra y lista clientes, estás conectada. Si dice que no tiene acceso, revisa que activaste Drive con tu cuenta @copywriters.cl y que Valeria te dio permiso a la carpeta.

5El arranque automático

En el chat de Claude (dentro de VSCode, con la carpeta del estudio abierta) escribe exactamente:

/arranque

Claude revisa e instala todo lo que falte, siembra la memoria del estudio (las 56 notas con todo lo aprendido de cada marca — sin esto Claude «olvida» meses de trabajo), verifica el conector de Drive, revisa tipografías y corre un diagnóstico. Si necesita algo de ti, te lo pide con la instrucción exacta. Déjalo terminar.

⚠️ Dile en tu primer mensaje que estás en Windows. Basta con «estoy en Windows» al pedir /arranque. El estudio nació en Mac y algunos comandos de sus manuales están escritos con rutas de Mac; avisando, Claude usa las de Windows sin equivocarse. El Python del estudio, por ejemplo, queda en C:\Users\tunombre\copylab-venv\Scripts\python.exe (en Mac es otra ruta). No tienes que memorizar eso — solo avisar.
✅ La prueba final de la instalación — pídele a Claude: «hazme una pieza simple de EBEMA para probar que todo funciona». Si en unos minutos tienes un PNG con la gráfica de EBEMA bien armada, tu estudio está operativo. Ese es el punto de llegada de esta guía.

6Tu rutina de todos los días

El estudio lo comparte el equipo completo. Para que cualquiera pueda retomar el trabajo de cualquiera (si alguien se enferma, si estás en otra ciudad), hay dos ritos diarios que no se negocian:

CuándoQué escribes en ClaudeQué hace
Al empezar el día/abrir hilton
(o la marca que toque)		 Trae lo que hicieron los demás, te resume dónde quedó el cliente y revisa qué hay nuevo en Drive
Al terminar el día/cierre hilton Anota en la bitácora del cliente qué hiciste y dónde quedó, y sube todo para que otra persona pueda seguir mañana
⛔ Si no haces /cierre, tu trabajo del día NO existe para el resto del equipo. Aunque el día haya quedado a medias — especialmente si quedó a medias. La bitácora puede decir «a medias, no entregar», pero tiene que estar subido.

Qué queda guardado y dónde — esto es clave para entender tu flujo

Tu trabajo puede nacer en dos mundos, y cada uno tiene su camino para quedar guardado y disponible para el resto del equipo:

🖥️ Lo hiciste CON el estudio
(Claude en VSCode)		🎨 Lo hiciste FUERA
(Illustrator, Photoshop, Canva a mano)
¿Queda en GitHub? Sí — cuando corres /cierre. Se guarda la «receta» de la pieza (los scripts y fondos que la generan), lo aprendido en el manual de la marca y la bitácora del día No llega solo. La pieza vive en Drive; para que el estudio la aprenda, hay que medirla y escribirla en el manual (Claude lo hace con /adn o cuando /abrir detecta trabajo nuevo)
¿Y la pieza final? El PNG/video entregado va a la carpeta de Drive del cliente — GitHub guarda el generador, no el archivo pesado A Drive, como siempre
¿Qué tienes que hacer tú? Solo /cierre al final del día — Claude hace el resto Subir la pieza aprobada a Drive y avisarle a Claude: «diseñé esto a mano para <marca>, apréndelo» — él lo mide y lo codifica en el manual
⚠️ Por qué importa: si llegas a un buen diseño y no pasa por uno de estos dos caminos, ese aprendizaje se pierde — el próximo que tome la marca (u otro diseñador cubriéndote) va a repetir los errores que tú ya resolviste. En GitHub no se guarda «el dibujo»: se guarda cómo se llega a él, que es lo que permite que cualquiera del equipo lo reproduzca y lo continúe.

Reglas de oro mientras trabajas (Claude también las conoce y te las va a recordar):

  • El brief manda el QUÉ; el sistema de la marca manda el CÓMO. Nunca inventes un estilo: cada cliente tiene su manual medido en clients/<marca>/.
  • Textos y CTAs salen literales del brief. Si falta un dato, se pregunta — no se inventa.
  • Ninguna pieza se muestra sin pasar el QA. Claude lo corre solo; si marca algo en rojo, se corrige antes de entregar.
  • Cuando un cliente corrige algo, se escribe en su manual ese mismo día. Díselo a Claude y él lo codifica.

7Cómo se parte con un cliente nuevo

Antes de diseñar NADA para una marca nueva, hay que juntar su material. Esta es la lista de lo que se pide — normalmente al KAM de la cuenta, que se lo pide al cliente:

#Qué pedirSi no está…
120 a 60 piezas aprobadas del diseñador actual del cliente, en una carpeta de Drive Se adivina el estilo y las primeras rondas se rechazan enteras
2Acceso de Drive a esa carpeta para tu cuenta Trabajas a ciegas
3Los archivos de tipografía reales (.otf / .ttf), o al menos el nombre exacto y de quién es la licencia Se diseña con sustitutos y el resultado «casi» calza. Ojo con las fuentes DEMO «personal use only»: no se pueden usar en trabajo de cliente
4Logos oficiales en PNG con transparencia — todas las versiones (para fondo claro, oscuro, horizontal…) Recrear un logo a mano es un error garantizado
5Editables empaquetados (.ai con su carpeta de Links) Sin ellos no se pueden extraer los colores y medidas exactos
6El brief con los textos finalesCuatro rondas de idas y vueltas
7Derechos de imagen: qué personas de las fotos se pueden publicar Se publica una cara sin permiso — problema legal del cliente y de la agencia

Con el material en la carpeta, en Claude escribes:

/marca-nueva nombredelcliente

Claude mide las piezas reales (colores píxel a píxel, tipografías, posiciones), arma el manual de la marca y hace el examen de admisión: reproducir una pieza ya aprobada desde cero. Solo cuando esa reproducción calza, la marca está lista para producir. Al final del día: /cierre, y el sistema del cliente nuevo queda disponible para todo el equipo.

⚠️ Tipografías en Windows: cuando el cliente te mande los .ttf o .otf, instálalos también en el sistema — botón derecho sobre el archivo → Instalar para todos los usuarios. Además hay que dejar una copia dentro del estudio para que las piezas rindan igual en todas las máquinas; pídeselo a Claude: «guarda estas tipografías en el estudio para <marca>».

Lo que había que arreglar para que corriera en Windows

Los scripts del estudio nacieron en Mac. Estas cuatro cosas fallaban en seco y ya están corregidas en el repo:

  • scripts/_entorno.py — python_venv() sólo miraba venv/bin/python3 y caía a la cadena "python3", que en Windows no existe como comando. Ahora mira venv\Scripts\python.exe y, si no hay venv, devuelve sys.executable.
  • scripts/drive-carpeta.py (nuevo) — reemplaza a hilton-drive-pull.sh, que llamaba a /usr/bin/python3 y guardaba los archivos con un \r pegado al nombre: Windows lo convertía en _ y todo quedaba como foto.jpg_.
  • scripts/between-rendir.py (nuevo) — reemplaza a between-rendir.sh, que tenía quemada la ruta de Chrome del Mac y un sandbox en ~/copylab-work que sólo existía para esquivar iCloud. Además fuerza UTF-8 al leer la salida de Remotion: con el cp1252 por defecto de Windows, el hilo lector de subprocess revienta.
  • .gitignore — credentials/ no estaba ignorada. Un token dejado ahí se habría publicado a todo el equipo en el siguiente push.

Comprobar el estado de la máquina en cualquier momento: python scripts\_entorno.py
